# 金元词人补全专项

## Goal

补齐名录 97 位无词作作者的作品缺失:金/元词人语料 + 名录异体重复清理。交付「缺失分类清单 + 异体合并方案 + 数据源评估」,合并实施依赖数据源就绪。

## Background

- 名录 1,564 人为全宋词+全金元词合并诗人表,但词库 JSON(21,050 首)未含金/元词人作品
- 97 人无词作分三类:①真金元词人(元好问、辛愿、段克己、段成己、吴激、党怀英等)②名录异体重复(侯真/侯置、元好问/元问好——同人两名两个名录行)③唐五代/花间词人语料缺失(冯延巳、韦庄、温庭筠等,超出金元范围但同属缺失)
- 相似名自动检测已跑通:元好问/元问好命中,其余多为误配需人工策展

## Requirements

- **R1 缺失分类清单**:脚本输出 97 人分类(金元/异体重复/其他),附 desc 证据;异体对自动候选(difflib >0.6)供人工确认
- **R2 异体合并方案**:确认后生成名录合并映射(弃名 → 保留名),评估对 db 的影响(仅名录表,无词作)
- **R3 金元数据源评估**:调研开源全金元词数据(chinese-poetry 等),评估覆盖(词人/词作数量)、格式、许可;给出合并方案(数据管道或手工录入)
- **R4 合并管道(如数据源就绪)**:外部词作 → db 增量合并 → prepare_db 重建;否则交付待办方案

## Acceptance Criteria

- AC1:97 人全量分类完成,清单 JSON 含证据与建议类别,人工可复核
- AC2:异体重复对清单(含自动候选)产出,与 m1-prd 已知案例(侯真/侯置)一致
- AC3:数据源评估报告(覆盖/格式/许可/接入成本)
- AC4:如数据源可用则完成合并验证(新增词作可查、名录去重)

## Out of Scope

- ⿰ 还原(阶段 3,独立任务)
- 唐五代花间词人语料补全(超出金元范围,仅归类不实施)

## 关键决策

- 异体合并是名录层操作(无词作,合并仅影响名录展示),先于数据补全
- 数据源接入优先复用现有 prepare_db.py 管道(外部词作 JSON → 合并 → 重建)
