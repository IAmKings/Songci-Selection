# 宋词 SQLite 数据库设计与数据迁移

## Goal

基于 `data/ciauthor.json`（1,564 位诗人）和 `data/ci.json`（21,050 首词）设计一套 SQLite 数据库，支持通过诗人快速关联其诗词作品，并在低内存低消耗环境下实现快速全文搜索。交付物为 `db/build.py` 构建脚本和 `db/songci.db` 数据库文件。

### 目标应用形态

CLI / 桌面应用，交付纯 `.db` 文件。数据库设计考虑后续多平台开发可移植性（移动端、Web 端均能直接使用同一份 `.db` 文件）。

## Background

### 数据现状

| 文件 | 大小 | 记录数 | 字段 |
|------|------|--------|------|
| `data/ciauthor.json` | ~330KB | 1,564 | `value`(ID), `name`(诗人名), `long_desc`(生平简介) |
| `data/ci.json` | ~8.5MB | 21,050 | `value`(ID), `rhythmic`(词牌名), `author`(作者名字符串), `content`(词作全文) |

### 关键发现

- 诗词与诗人的关联靠 **作者名字符串** 匹配，非 ID 外键 — 这是数据库设计的核心问题
- 1,467/1,468 诗人名匹配（1 个不匹配："富ノ"，可能是数据录入错误）
- 1,423 种唯一词牌名
- 词作平均长度 87 字符，最长 666 字符；全文为中文字符，无空格分词
- 数据源为静态 JSON 文件，变更频率极低，适合一次性迁移生成

## Requirements

### R1: 数据库 Schema 设计

**核心数据表（源 JSON 派生，可重建）：**
- 诗人表（authors）：以 `ciauthor.json` 的 `value` 为主键 ID
- 词作表（poems）：以 `ci.json` 的 `value` 为主键 ID，通过 `author_id` 外键关联诗人，`rhythmic`（词牌名）存为字段
- 全文搜索采用 SQLite FTS5 虚拟表（unicode61 tokenizer，零外部依赖，CJK 逐字分词）

**应用数据表（用户数据，独立于核心表，重建时保留不动）：**
- 收藏表（favorites）：`poem_id` 外键关联 poems，`created_at` 时间戳
- 后续新增功能均通过增加应用表实现，不修改核心表结构

### R2: 数据迁移
- Python 构建脚本读取两个 JSON 文件，完成名字→ID 匹配，写入 SQLite
- **首次构建**：创建全部表（核心表 + 应用表）
- **重建**：仅 DROP 核心表后重建；应用表（favorites 等）保留不动，用户数据不丢失
- 处理边界情况："富ノ" 保留诗词数据，author_id 设为 NULL
- 迁移结果可复现（幂等）

### R3: 搜索能力
- 按诗人姓名精确/模糊查询
- 按词牌名查询该词牌下所有词作
- 按诗词内容全文搜索（支持中文，< 100ms）
- 支持组合条件查询（如：某诗人的某词牌、收藏+关键词）

### R4: 低内存低消耗
- 数据库文件大小 ≤ 20MB
- 搜索不依赖外部服务，纯本地 SQLite 查询
- 零外部扩展依赖（不依赖 ICU、JSON1 等）

### R5: 收藏标记
- 独立的 `favorites` 表，字段：`poem_id`（FK → poems.id）、`created_at`（默认当前时间）
- 与核心数据表分离，重建数据库时收藏数据不丢失
- 应用端通过 INSERT/DELETE 操作 favorites 表实现收藏/取消收藏
- 支持 JOIN 查询：收藏的词作列表、某诗人被收藏的词作等

## Acceptance Criteria

- [ ] 数据库包含 authors 表和 poems 表，通过 author_id 外键正确关联
- [ ] 独立的 `favorites` 表，外键关联 poems.id
- [ ] 21,050 首词全部迁移，1,564 位诗人全部迁移
- [ ] "富ノ" 的诗词可查询但其 author_id 为 NULL
- [ ] 按诗人名查询词作结果正确（如查"苏轼"返回其所有词作）
- [ ] 全文搜索在 < 100ms 内返回匹配结果
- [ ] 词牌名查询结果正确（含词牌名统计数量）
- [ ] 收藏 JOIN 查询正确（favorites JOIN poems）
- [ ] 重建数据库后，favorites 数据保留不变
- [ ] 数据库文件大小 ≤ 20MB
- [ ] 提供可复现的构建脚本（Python 3 标准库，无第三方依赖）

## Out of Scope

- 数据库的增删改维护功能（仅需构建生成；is_favorite 由应用端运行时修改）
- API 服务端封装
- 前端 UI 实现
- 诗词数据校对/修正
