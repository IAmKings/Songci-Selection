### P1-1 详情页超长句整句换行,破坏竖排

**证据**:`DetailScreen.kt:155-180` `StanzaColumn`/`PoemLines` 中词句 `Text` 无 `maxLines`/换行限制;数据层 **>40 字单句 299 句**(>30 字 486 句,最长 78 字),如:

```
[57字] 江海渺千里,飘荡叹流年。等闲匹马相过,乘兴却翛然。十载悲欢如梦,抚掌惊呼相语,往事尽飞烟。此会真难偶,此醉且留连。(水调歌头)
[71字] 羊角飘尘,金乌烁石,雨凉念秋。有虚堂临水,披襟散发,纱雾卷,湘潭波浮。远列云峰,近参荷气,卧看文书琴枕头。(沁园春)
```

**影响面**:窄屏(30dp padding)与宽屏双栏下,长句自动换行成 2-3 行,与宋词"一句一行"竖排排版意图冲突,视觉上"异常"。

**成因**:数据源格式为"一行 = 多韵句连排"(非缺陷),需产品判断是否按韵句断行。若断行,需以格律谱(平仄/韵脚)或标点为依据,改动面较大,建议单独立项评估。

**状态:保持观察项(未实施)**——完整改法为数据层按韵脚/标点重排(高风险,需格律校验回归),报告已建议单独立项评估;本次不做。若需 UI 层语义断行,另立任务。

### P1-2 通知首句超长推送

**证据**:`DailyNotification.kt` 复用 `randomPoems`,推送「词牌·作者 + 首句」;首句可为 40-78 字长句(如上述沁园春)。

**影响面**:系统通知被超长文本撑满/截断,观感差。

**处置(2026-08-16 已实施)**:commonMain 新增 `Poem.notificationFirstLine(24)`(截断 + 省略号),Android/iOS/macOS 三端通知统一调用;全库截断后首句 ≤25 字(验证通过)。

### P2-1 卡片摘录硬切无省略号

**证据**:`components/Common.kt:28` `excerpt = poem.content.lineSequence().firstOrNull()?.take(18) ?: ""`,18 字硬切,无 "…"。

**影响面**:首页推荐流/搜索结果卡片中,长句摘录以"半句"结束,无截断视觉提示。

**处置(2026-08-16 已实施)**:`Common.kt` 摘录超 18 字补 "…"(369 首触发);全库摘录 ≤19 字(验证通过)。

### P2-2 卡片词牌名无行数限制

**证据**:`components/Common.kt:42` `Text(poem.rhythmic, headlineMedium)` 与作者名 `SpaceBetween` 同行,无 maxLines;词牌最长 15 字(≥10 字 63 首)。

**影响面**:15 字词牌在窄屏可能挤压作者名或换行,卡片标题行错位。

**处置(2026-08-16 已实施)**:`Common.kt` 词牌 `maxLines = 1` + `TextOverflow.Ellipsis`(15 字词牌单行省略,作者名不再被挤压)。
